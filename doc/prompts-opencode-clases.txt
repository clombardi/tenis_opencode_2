## Análisis del PlayerForm.tsx

El formulario actual tiene validaciones básicas (campos requeridos, tipo email del navegador). Aquí te sugiero validaciones adicionales útiles:

### Validaciones sugeridas

| Campo | Validación propuesta |
|-------|---------------------|
| **firstName/lastName** | Solo letras y espacios, máximo ~50 caracteres |
| **email** | Formato válido, verificar disponibilidad (ya que es unique en backend) |
| **documento** | Solo números, longitud específica (ej: 8 dígitos para DNI argentino) |
| **birthDate** | No futura, rango razonable (ej: no mayor a 100 años, no menor a 10 años) |
| **country** | Autocomplete con lista de países (evita texto libre) |

### Implementación recomendada

1. **Estado de errores**: Agregar un objeto `errors` al state:
   ```typescript
   const [errors, setErrors] = useState<Record<string, string>>({});
   ```

2. **Función de validación** antes de `handleSubmit`:
   ```typescript
   const validate = () => {
     const newErrors: Record<string, string> = {};
     if (!/^[a-zA-Z\s]+$/.test(formData.firstName)) {
       newErrors.firstName = 'Solo letras permitidas';
     }
     // ... otras validaciones
     setErrors(newErrors);
     return Object.keys(newErrors).length === 0;
   };
   ```

3. **Mostrar errores en campos**: Usar props `error` y `helperText` de MUI:
   ```tsx
   <TextField
     label="Nombre"
     value={formData.firstName}
     error={!!errors.firstName}
     helperText={errors.firstName}
     // ...
   />
   ```

4. **Librería opcional**: Considerar **react-hook-form** + **yup** para validación declarativa más robusta.
